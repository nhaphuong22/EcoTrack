## Intent

**Problem:** Currently, LLM model names are hardcoded in `orchestrator.py` (`gemini-1.5-flash` and `gpt-4o-mini`). When a cloud provider raises an exception, the exception is swallowed silently with `pass`, leaving operators unable to tell whether the answer was generated by Gemini, OpenAI, or the heuristic fallback. FR16 and NFR9 require:
1. Provider failures logged with provider name and reason as warnings.
2. Model names configured through `GEMINI_MODEL` and `OPENAI_MODEL` environment variables.
3. Every Copilot response stating which engine produced it (`gemini`, `openai`, or `heuristic`).

**Approach (Ponytail - lean, zero overhead):**
- In `ai-service/src/config.py`: Add `GEMINI_MODEL` (default: `"gemini-1.5-flash"`) and `OPENAI_MODEL` (default: `"gpt-4o-mini"`).
- In `ai-service/src/agent/orchestrator.py`:
  - Read model names from `src.config`.
  - When Gemini call throws: Log warning `logger.warning(f"[Copilot] Gemini provider failed ({GEMINI_MODEL}): {err}")`. Fall through to OpenAI.
  - When OpenAI call throws: Log warning `logger.warning(f"[Copilot] OpenAI provider failed ({OPENAI_MODEL}): {err}")`. Fall through to heuristic.
  - Track `engine`: `"gemini"`, `"openai"`, or `"heuristic"`.
  - Return `engine` in response and log to `experiment_logger`.

## Boundaries & Constraints

**Always:**
- No hardcoded model names in `orchestrator.py`.
- Log provider failures with logger level WARNING, containing provider name and error string.
- Response payload must include `"engine": "<gemini|openai|heuristic>"`.
- Existing `reply` and `tools_used` fields remain unchanged.
